# Poke Marble — 관동·성도 보드게임

비공식·비상업 포켓몬 팬 프로젝트입니다. 관동·성도 **32칸 맵에서 사람 1명과 AI 3명이 플레이**할 수 있습니다. 자체 코드의 라이선스는 **미정**이며, 에셋·데이터의 권리와 별개입니다.

> 이 설명은 현재 통합 브랜치의 코드 기준입니다. 원격 main에 반영됐다는 뜻은 아닙니다. 능동 기술의 선택 설명·PP HUD·합법 선택·발동 연출을 연결했으며, 검증 범위와 한계는 [7개 작업 통합 기록](docs/integration-seven.md)을 참고하세요. 기술 수치의 균형이 확정됐다는 의미는 아닙니다.

## 게임 흐름

1. `NEW GAME` → 이상해씨·파이리·꼬부기·피카츄 중 파트너 선택. 나머지 세 파트너는 컴퓨터에게 배정됩니다.
2. 관동·성도 맵과 표준 또는 짧은 경기 규칙을 선택해 시작합니다. 다른 지방은 준비 중입니다.
3. 주사위를 굴려 이동합니다. 구매·건설·통행료·인수·매각은 표시된 권위 견적과 합법 선택으로 처리합니다.
4. 턴을 마치면 AI가 같은 규칙으로 진행합니다. 공중날기는 카드 선택 후 별도 확정하며, 전설시험·가호·탈출로프의 결과와 재고를 HUD에서 확인합니다.
5. 승리 결과를 확인한 뒤 새 경기를 시작할 수 있습니다.

보드·이동·건물·폰은 Phaser, 메뉴·구매창·HUD는 HTML/CSS입니다. 도시 목록·자산·소리·크레딧은 해당 버튼으로 열며, 작은 화면의 긴 목록과 상세 정보는 내부 스크롤을 사용합니다. 기존 왼쪽 상시 음소거 패널은 없고 `소리`에서 설정합니다. 연출 스킵·감소 모션에서도 확정된 거래를 다시 실행하지 않습니다. 기본 4종 초상화·표정, 루기아·칠색조 시험, 가호·로프 결과 안내가 연결되어 있습니다.

## 구현 상태와 후속 규칙

| 범위             | 상태                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------ |
| 실제 게임        | 32칸·경제·AI 3명·전설 기믹·4종 즉시 승리·재시작                                      |
| 화면과 경기 설정 | 모바일 프레이밍, 공개정보 AI, 표준/quick 프리셋, 제한 라운드, 중앙 턴 헤더·승리 진척 |
| 능동 기술        | 3PP·공개 후 이동 선택·경제 기술 견적・자동 특성 정산 제거・AI 합법 사용              |
| 기술 UI          | 선택 설명·PP HUD·발동 연출·스킵/초기화 완료 처리 연결                                |

현재 통합 코드에서 다음 두 규칙을 선택할 수 있습니다.

| 규칙                                         | 표준                               | 짧은 경기   |
| -------------------------------------------- | ---------------------------------- | ----------- |
| 제한 라운드                                  | 30                                 | 20          |
| 개인 완료 주회별 camp/shop/center/final 해금 | `[0,0,1,2]`                        | `[0,0,1,1]` |

개인 주회, 기본차례, 전체 라운드는 서로 다릅니다. 즉시 승리 네 조건은 **마지막 생존자 / 도시 그룹 3개 / 한 변의 일반 도시 독점 / 특별 명소 4곳**입니다. 제한 라운드에서는 마지막 기본차례의 정산을 마친 뒤 현금과 보유 부지·누적 건설 원가로 순위를 정합니다. 동점은 현금, 원래 좌석 순서로 구분합니다. 미확정 주사위·통행료·채무가 있으면 종료와 자산 순위를 보류합니다.

상세 계약은 [건설 프리셋](docs/construction-rule-presets.md), [제한 라운드](docs/round-limited-match.md), [턴 헤더](docs/turn-progress-header.md)에 있습니다. 시험 모서리의 소용돌이섬·방울탑과 일반 명소 분노의호수·용의굴은 서로 구분합니다.

## 능동 기술 검증 시작안

실제 게임은 다음 능동 기술을 사용하며 자동 특성 현금 환급을 지급하지 않습니다. 독립적인 과거 자동 특성 시연 모듈은 남아 있으며, 실제 게임 규칙과 구분합니다. 선택 화면과 경기 중 `기술 정보`에서 효과·사용 조건을 확인할 수 있습니다.

공통 자원은 **초기 3PP, 자동 충전 없음, 개인 기본차례당 실제 사용 1회**이며 별도 쿨다운은 없습니다. 원래 주사위 합계 유지는 PP를 소비하지 않습니다. 시험·비행·강제이동에는 사용하지 않습니다.

| 파트너 / 기술       | 고유 효과와 시점                           |
| ------------------- | ------------------------------------------ |
| 이상해씨 / 덩굴채찍 | 눈 공개 후 이동 전, 원래 합계 유지 또는 −1 |
| 꼬부기 / 물대포     | 눈 공개 후 이동 전, 원래 합계 유지 또는 +1 |
| 파이리 / 불꽃세례   | 착지 의무 통행료 25% 감소, 최대 100        |
| 피카츄 / 전기쇼크   | 합법 일반 도시 인수금 20% 감소, 최대 100   |

이동 합계는 2~12 범위이며 최종시설·명소 인수 면역은 유지합니다. 네 파트너 모두 고유 효과 대신 **기술 돌파: 통행료 15% 감소·최대 60**을 선택할 수 있으며 같은 PP를 쓰고 고유 효과와 중첩하지 않습니다. 상성 우위는 경제 효과에만 할인율 +10%p·상한 +25입니다. 불→풀, 물→불, 풀→물, 전기→물만 우위이며, 상시 타입 할인·열세 벌금·이동 기술의 무료 추가 보너스·가짜 순환 상성은 없습니다.

이는 균형 검증이 끝난 수치가 아닙니다. 가호와 기술은 한 권위 견적에서 정산하고 중복 소비를 막습니다. 작은 좌석 교차 표본은 [통합 기록](docs/integration-seven.md)에 한계와 함께 남겼습니다. 철회된 2~6/8~12 주사위·일괄 50% 기술 초안은 현재 사양이 아닙니다.

## 로컬 실행

Node.js **22.17 이상**과 npm을 사용합니다. PowerShell에서 실행 정책으로 `npm.ps1`이 차단되면 아래처럼 `npm.cmd`를 사용하세요.

```powershell
npm.cmd ci
npm.cmd run dev
```

표시된 로컬 주소(기본 `http://127.0.0.1:5173`)를 Chrome에서 엽니다. 설치 이후 기본 화면·빌드에는 PokeAPI나 SpriteCollab 연결이 필요하지 않습니다. 외부 링크를 직접 열 때만 원 사이트로 이동합니다.

| 명령                                      | 역할                                              |
| ----------------------------------------- | ------------------------------------------------- |
| `npm run dev`                             | Vite 로컬 개발 서버                               |
| `npm run typecheck`                       | TypeScript 엄격 모드 검사                         |
| `npm run lint`                            | TypeScript·수집 스크립트 ESLint 검사              |
| `npm run format` / `npm run format:check` | 자체 코드·문서 정렬 / 확인                        |
| `npm run build`                           | 타입검사 후 `dist/` 정적 빌드                     |
| `npm run preview`                         | 빌드 결과 로컬 확인                               |
| `npm run data:generate`                   | 저장된 응답에서 한국어 JSON 재생성, 네트워크 없음 |
| `npm run data:fetch`                      | PokeAPI 응답 8개를 순차 갱신하고 JSON 생성        |
| `npm run assets:sync`                     | 고정 커밋에서 샘플 시트·크레딧·정책 원문 재수집   |
| `npm run assets:verify`                   | 로컬 외부 파일의 출처 manifest와 SHA-256 비교     |

스크립트에서 실패하면 비정상 종료합니다. 데이터 수집 실패·한국어 누락·스냅샷 해시 불일치를 빈 데이터로 조용히 대체하지 않습니다. 생성 JSON과 원본 스냅샷은 함께 버전 관리하고, 원본 외부 파일은 포맷터 대상에서 제외합니다. `package-lock.json`을 함께 유지해 `npm ci`로 설치하세요.

## 역할 분리

```text
src/game/             공통 타입·core·경제·AI·승리·전설 규칙
src/data/             실제 관동·성도 맵, 포켓몬 데이터 어댑터
  sources/pokeapi/     원본 응답과 요청 URL·수집 시각·SHA-256
  generated/          가공한 한국어 JSON
src/assets/           에셋 조회, 고정 ID와 로컬 URL 연결
  vendor/             수정하지 않은 외부 PNG/XML/크레딧/정책
  generated/          제작자·조건·원본 URL·프레임·해시 manifest
src/ui/               실제 게임 연결, Phaser 보드, HTML 메뉴·HUD·연출
scripts/              재현 가능한 수집·가공·무결성 검증
docs/                 후속 계약과 원 출처 권리 검토 기록
```

기본 계약은 [공통 계약과 ID 규칙](docs/contracts.md), 검증된 main의 통합 기록은 [후속 네 UI 통합](docs/integration-followup-four.md)을 참고하세요. 계약 문서 중 초기 설계 기록과 현재 구현 상태는 구분해야 합니다. 게임 저장·이어하기는 구현하지 않았습니다.

## 스프라이트와 한국어 데이터

기본 4종에 대해 Idle·Walk **8개 PNG 시트**와 원본 XML을 로컬 보관합니다. 8방향 행과 XML의 프레임별 duration(60 tick/s)을 사용합니다. 실제 보드 폰, HUD 초상화와 전설 시험은 각각 별도 표시 모듈이며, 초기 실험실/preview 화면을 실제 게임 진입과 혼동하면 안 됩니다. OS의 동작 줄이기와 로드 실패 대체를 지원합니다.

- 루기아·칠색조 시트와 개별 근거: [ASSETS.md](src/ui/game/events/ASSETS.md), [manifest](src/ui/game/events/assets/manifest.json).
- 기본 4종 HUD 초상화: [portrait 안내](src/ui/game/portraits/README.md), [개별 manifest](src/ui/game/portraits/manifest.json), [정책 원문](src/ui/game/portraits/evidence/LICENSE.md). 전설 시트 사용이 별도 전설 초상화 수집을 뜻하지 않습니다.
- 로컬 Galmuri11: [도입·출처 기록](docs/ui-polish.md), [SIL OFL 원문](src/ui/game/theme/fonts/LICENSE.txt), [고정 revision·해시](src/ui/game/theme/fonts/provenance.json).

데이터 수집 대상은 [scripts/samples.json](scripts/samples.json)에서 고정합니다. `pokemon/{id}`의 식별자·타입과 `pokemon-species/{id}`의 `names`·`genera` 중 `language.name === "ko"`인 값을 합칩니다. 지역 형태나 여러 폼의 ID 변환은 구현하지 않았습니다. 원본 응답 해시와 수집 시각은 각 `.source.json`과 가공 JSON에 보존합니다. REST 응답 자체는 변경될 수 있으므로 **동일 결과 재현에는 저장된 스냅샷과 `data:generate`를 사용**하세요. `data:fetch`는 명시적인 갱신 작업입니다.

[PokeAPI 공식 문서](https://pokeapi.co/docs/v2/)의 로컬 캐시 권고를 따릅니다. API 접근 정책과 포켓몬 콘텐츠의 저작권·상표권은 별개입니다.

## 권리와 크레딧

**자체 코드, 외부 에셋, 외부 데이터의 권리를 분리합니다.** `package.json`의 `UNLICENSED`는 자체 코드 라이선스가 미정이라는 표시이며, 외부 자료의 권리를 제한하거나 허락하는 표기가 아닙니다. 의존 패키지는 각 패키지의 라이선스를 따릅니다.

- Pokémon의 원작·캐릭터·명칭 관련 권리: Nintendo / Creatures Inc. / GAME FREAK inc. 등 원 권리자.
- Pokémon Mystery Dungeon 원작 스프라이트 관련 권리와 제작: Chunsoft / Spike Chunsoft 등. 원작 권리를 팬 제작자의 창작 기여 권리와 혼동하지 않습니다.
- 이미지 제공 경로: [PMD Sprite Repository](https://sprites.pmdcollab.org/) 및 [PMDCollab/SpriteCollab](https://github.com/PMDCollab/SpriteCollab).
- **이번 4종의 개별 제작자 기록은 모두 `CHUNSOFT`, 개별 라이선스는 `Unspecified`입니다.** 팬 제작자 이름을 임의로 붙이지 않았습니다. 일반 제출물에 대한 CC BY-NC 4.0 정책이 원작 추출물에 대한 허락을 보장한다고 주장하지 않습니다. 원 권리자의 별도 사용 허락은 확인되지 않았으며, 공개·재배포 전에 이를 별도로 검토해야 합니다.
- 팬 제출물을 추가할 때는 해당 슬롯의 제작자·기여 기록·라이선스·변경 내역을 개별 검토해 manifest와 안내에 반영해야 합니다. 원본 출처가 명시한 저작권·면책 고지도 유지하세요.
- 한국어 명칭 등 데이터 제공: [PokeAPI](https://pokeapi.co/docs/v2/). API 서버 코드의 라이선스를 데이터와 포켓몬 콘텐츠 전체의 라이선스로 간주하지 않습니다.

4종의 개별 제작자·기여 날짜·원본 URL·라이선스 식별자·수정 여부·해시는 [sprites.json](src/assets/generated/sprites.json)에 있으며 원본 `credits.txt`를 함께 보관합니다. 확인한 정책 원문과 예외는 [권리 검토 기록](docs/rights.md)을 참고하세요.

본 프로젝트는 공식 작품이 아니며 원 권리자 또는 SpriteCollab의 승인·제휴를 의미하지 않습니다. 비공식·비상업 안내만으로 별도 이용 허락이 생기는 것은 아닙니다.

### 권리자 삭제 요청

권리자의 요청이 있으면 해당 자료의 사용을 중지하고 저장소·빌드 결과에서 신속히 제거합니다. 요청 식별에는 대상 파일/URL, 권리 관계, 요청 범위가 필요합니다. **실제 요청 수신 창구는 아직 미정이며, 연락처나 요청 폼을 만들어 기재하지 않았습니다.** 공개하기 전에 운영자가 실제로 확인할 수 있는 창구와 담당자를 정해야 합니다.

저장/이어하기, 온라인 대전과 다른 지방은 구현하지 않았습니다. 더블 연속 굴림·START 추가 건설·저장 신규 작업은 이번 범위에 착수하지 않았습니다. 기술 수치의 균형 확정, 최종 코드 라이선스, 외부 자료 재배포 허락, 삭제 요청 수신 창구도 미정입니다. Git 원격 백업은 웹 배포나 외부 권리 허락을 뜻하지 않으며, GitHub Pages 활성화는 이 작업 범위가 아닙니다.
