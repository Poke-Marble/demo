## 2. 원작 확인과 자체 제안의 경계

원출처: [넷마블 모두의마블 PC 공식 게임진행 안내](https://modoo.netmarble.net/guide/Contents.asp?depth1=324&depth2=1501&depth3=3079&id=gmm&title=), 2026-11-18 본문 확인. 모바일·후속 모드 전체에 적용되는 최신 통합 규칙이라고 일반화하지 않는다. 아래는 요약이며 원문/이미지 복제는 하지 않는다.

| 공식 안내에서 확인한 내용                               | Poke Marble에서의 취급                            |
| ------------------------------------------------------- | ------------------------------------------------- |
| 무주지 도착 구매, 구매와 건설 병행, 관광지는 건설 불가  | 도시 구매·건설과 관광명소 별도 규칙의 참고 근거   |
| 별장·빌딩·호텔과 출발 통과에 따른 해금                  | 개인 바퀴수 권장 근거. ‘첫번째턴/두번째턴’과 다름 |
| 세 건물이 있는 도시에 도착하면 랜드마크 건설            | 최종시설의 전제·재방문 조건을 별도로 설계         |
| 컬러독점 통행료 2배, 소유 상실 시 해제                  | 그룹 2배 초안의 참고 근거                         |
| 건설된 도시 가격 2배 인수, 랜드마크 인수 불가·공격 방어 | 인수/면역은 별도 승인 대상으로 남김               |
| 최후 생존·세 색 그룹·한 라인·관광지 독점 승리           | 기존 `VictoryReason` 네 종류와 대응               |

원작의 부지 + 별장 + 빌딩 + 호텔 + 랜드마크를 다섯 상태로 셀 때, 여기서는 캠프(부지 포함) + 숍 + 센터 + 최종시설 네 상태로 줄었다. ‘캠프 뒤에 원작 건물 네 개’를 덧붙이면 다섯 단계가 되어 확정 방향과 어긋난다. 연구소·백화점·실프·라디오타워·등대 등 도시 정체성, 시험 가호, 개인 바퀴수의 정확한 정의와 아래 수식·원자적 API는 자체 제안이다. 공식 가이드의 제한시간/제한턴 자산 순위, 더블, 축제·올림픽·공격 전체는 이번 MVP에 도입하지 않는다. main 코어도 더블 추가턴을 구현하지 않는다.

공식 안내의 순서는 최초 별장, 출발 첫 통과 후 빌딩, 두 번째 통과 후 호텔이며 랜드마크는 기존 세 건물과 해당 도시 도착을 전제로 한다. 아래 해금 A/B안은 그 순서를 네 단계에 맞춰 다시 설계한 것이며 원작의 표를 그대로 옮긴 것이 아니다.

## 3. 건설 상태와 숍/센터의 두 해석

소유하지 않은 상태는 단계 바깥 `unowned`다. 소유 시 캠프가 생기며 깃발은 지역 확보를 표시한다. 캠프에 주택 모형을 요구하지 않는다.

| 단계       | 공통 의미          | A안: 별도 누적시설(권장)        | B안: 순차 레벨         |
| ---------- | ------------------ | ------------------------------- | ---------------------- |
| 0 `camp`   | 부지 확보          | 깃발만 보유                     | 캠프 레벨              |
| 1 `shop`   | 첫 개발            | 숍을 추가                       | 캠프를 숍으로 전환     |
| 2 `center` | 두 번째 개발       | 숍과 센터를 함께 보유           | 숍을 센터로 전환       |
| 3 `final`  | 도시 대표 최종시설 | 앞선 시설 충족 후 대표시설 추가 | 센터를 대표시설로 전환 |

**숍과 센터가 별도 시설인지 순차 레벨인지는 사용자 미확정이다.** A안은 여행 거점이 성장하는 의미와 동시건설 견적을 표현하기 좋다. 단, 모형이 늘어나는 공간·아트 비용이 있다. B안은 기존 `facilityLevel: 0..3` 및 단일 모형 렌더에 가깝지만 센터가 되면 숍이 없어지는 의미가 된다. A안을 추천하되 한 타일에 모든 모형을 독립 배치하도록 강제하지 않는다. 아트는 합성 모형이나 대표 모형+보유 표식으로 누적 상태를 보여줄 수 있다.

두 안 모두 단계 건너뛰기는 **중간 단계 비용을 포함한 하나의 거래**로만 가능하다. A안의 보유 집합은 `[]`, `[shop]`, `[shop, center]`, `[shop, center, final]` 네 prefix만 허용한다. 임의로 센터만 선택하는 A안은 별도 규칙 변경이다. B안도 비용은 차액 시세가 아니라 미결제 전환 비용의 합이다. 통행료는 두 안 모두 도달 단계의 **전체 통행료 표**를 사용하므로 시설별 통행료를 다시 더하지 않는다. 중간 시설만 철거/매각하는 기능은 제안하지 않는다.

## 4. 개인 바퀴수와 4단계 해금 비교

`completedLaps[playerId]`는 0으로 시작한다. 일반 주사위 이동으로 출발선을 통과하거나 출발에 정확히 도착할 때 `passes`만큼 증가한다. 초기 배치는 증가하지 않는다. 출발이 배열 0이 아닐 수도 있으므로 ID 숫자나 화면 위치로 판단하지 않는다. 코어의 `start-rewarded.passes`와 같은 이동 계산을 사용하되, 보상 금액이 0이어도 횟수는 증가한다. 복수 통과는 복수 횟수다.

`GameState.turnNumber`는 사람/AI 차례가 시작될 때마다 증가하는 전역 차례 번호다. 개인 차례 횟수·라운드·개인 바퀴수와 다르다. 사용자가 말한 ‘첫번째턴/두번째턴’을 개인 첫/둘째 차례로 해석하면 출발점을 통과하기 전에 고급 건설이 가능해 원작과 달라진다. 느린 이동이나 시험 체류로 차례만 소비해도 해금되는 문제를 피하려고 **개인 출발선 통과 기반**을 권장한다. 시험 체류·성공·로프 사용만으로는 바퀴수를 올리지 않는다. 비행은 출발 착지까지 포함해 0회로 센다.

| 후보              | 0바퀴   | 1바퀴                 | 2바퀴 이상                 | 장단점                                                                      |
| ----------------- | ------- | --------------------- | -------------------------- | --------------------------------------------------------------------------- |
| A 보수형          | 캠프·숍 | 센터                  | 최종시설(재방문 전제 포함) | 원작의 두 번 통과 템포를 보존하나 4단계에서 대기감이 길다.                  |
| B 압축형 **권장** | 캠프·숍 | 센터, 조건부 최종시설 | 동일                       | 줄어든 한 단계를 반영. 최종시설은 별도 재방문이 필요해 첫 방문에 완성 불가. |

개인 해금은 소유 도시 모두에 적용하고 인수받은 시설을 철거하지 않는다. 예를 들어 0바퀴 플레이어가 센터 도시를 인수해도 센터는 유지하지만, 본인의 해금과 재방문 조건을 충족하기 전 최종시설은 못 짓는다. 출발 통과와 착지가 같은 이동이면 바퀴수 갱신을 먼저 하고 도착지 건설 견적에 반영한다. **B안과 1바퀴 수치는 승인 전 추천**이다.

### 최종시설 전제와 재방문

권장안은 본인 소유 도시, 숍·센터 완료, 개인 해금 충족, 유효한 대표시설 키가 있어야 한다. 더하여 **현재 소유자가 센터 완성 상태를 보유한 이후의 새로운 착지**여야 한다. 센터를 현재 착지에서 지은 뒤 모달을 다시 열어 최종시설을 만드는 것은 불가하다. 센터가 있는 도시를 인수했다면 인수 착지도 최종 건설 기회가 아니며 인수 후 새 착지가 필요하다.

`centerReadyVisitOrdinal`을 기록하고 현재 도시 착지 순번 `visitOrdinal`이 더 클 때만 허용한다. 인수 시 새 소유자 기준으로 현재 순번에 재설정한다. 비행으로 새로 도착한 것은 새 방문으로 인정한다. 통과, 조회, 연출 재생, 새로고침, 같은 착지에서 액션 여러 번은 새 방문이 아니다. 미리 센터가 있던 본인 도시에 1바퀴를 채우고 도착하면 바로 최종시설을 건설할 수 있다. 같은 방문에는 비최종 건설 거래 한 번만 허용하며 이후에는 정보 조회/턴 종료만 제공한다.

최종시설은 체육관·연구소 등 종류와 관계없이 같은 경제 단계다. 종별 특수 보너스는 이번 설계에 없다. 최종시설의 **인수 면역만 권장 초안**으로 둔다. 원작의 모든 공격 방어를 그대로 이식하지 않는다. 자진 매각·채무 청산·파산 처분까지 면제하지 않으며, 통행료 면제나 가호 무효도 의미하지 않는다.

## 5. 도시 정체성·라인·도시그룹

지도 정의의 `tiles` 순서·`side`·`cityGroups.cityIds`를 유일한 기준으로 소비한다. 경제 모듈은 배열을 재정렬하거나 임의 그룹을 만들지 않는다. 가격 등급은 여행 스토리 배치 이후 조절할 수 있으나 값싼 도시끼리 모으기 위해 동선을 바꾸지 않는다.

현재 trials v2의 관동 시작(태초·상록·회색), 해안(연분홍·홍련·사파리), 성도 시작(연두·무궁·도라지), 서부(고동·금빛·담청) 등은 참고할 연결이다. 관동 중심의 달맞이산, 정상 그룹의 검은먹·은빛산·석영은 여행·이야기 연결을 poke-trials가 재검토할 대상이다. 이 문서는 교체나 재배치를 확정하지 않는다.

| 기존 tile slug 예시                                         | 대표시설 메타 후보                             | 경제 소비                                                                          |
| ----------------------------------------------------------- | ---------------------------------------------- | ---------------------------------------------------------------------------------- |
| `pallet`, `new-bark`                                        | 오박사 연구소, 공박사 연구소                   | `finalFacilityKey` 참조, 종류별 가격 보너스 없음                                   |
| `celadon`                                                   | 무지개 백화점                                  | 같은 최종 단계                                                                     |
| `saffron`                                                   | 실프주식회사                                   | 아트의 현재 `gym` 장면과 의미가 달라 조정 필요                                     |
| `goldenrod`                                                 | 라디오타워                                     | 아트의 현재 `center` 장면과 구별                                                   |
| `olivine`                                                   | 등대                                           | 항구 배경과 대표시설은 공존 가능                                                   |
| `pewter`, `cerulean`, `blackthorn`                          | 도시별 체육관                                  | 일괄 체육관 규칙으로 확대하지 않음                                                 |
| 일반 명소 `mt-moon`, `ruins-alph`, `mt-silver`, `indigo` 등 | 관측소·조사거점·산장·리그시설 같은 게임용 후보 | 실제 도시가 아니어도 `kind: city`인 개발 가능 목적지. 명칭 검증·선택은 poke-trials |

이 표는 사용자 방향을 구체화한 **후보**이며 시설의 원작 존재/공식 명칭을 모두 검증한 지도 데이터가 아니다. `finalFacilityKey`는 번역 문자열과 분리하고 poke-trials가 메타를 발행한다. 모든 개발 가능 도시가 키를 갖기 전에는 final 행동을 합법으로 내보내지 않으며 누락을 체육관으로 대체하지 않는다.

## 6. 가격·건설 거래 불변조건

금액 단위는 임시 정수 코인이다. 모든 금액·곱·합·최종 잔액은 음이 아닌 안전한 정수여야 한다. 초과/NaN/누락 가격은 거래 전체를 거부한다. UI에서 보낸 금액은 신뢰하지 않고 규칙 계층이 다시 계산한다.

기존 맵 seed를 사용한 **비교용 초안**: 그룹 순위 `r=0..7`에 부지 `P=100+30r`, 숍·센터·최종 추가비 각각 `P/2`, 단계 전체 통행료 `[P/10,P/2,P,2P]`. 도시마다 추가비가 세 개이고 부지 포함 총 원가는 `2.5P`다. 이 수치가 균형 검증되거나 사용자 승인되었다는 의미는 아니다. 시세·가격 변동·유지비는 없다.

1. 무주 도시를 사면 캠프를 확보한다. 부지 대금 `P`는 필수이며, 숍·센터를 포함해 구매할 때도 한 번만 낸다. 미소유 도시에 시설만 설치할 수 없다.
2. 이미 소유한 부지와 기존 시설은 재결제하지 않는다. 목표 단계가 현재 이하이면 `already-built`로 거부한다. 중복 요청을 비용 0의 성공으로 처리하지 않는다.
3. 동시건설 비용은 **새로 생기는 모든 단계**의 비용을 합한다. 같은 착지에서 여러 번 할인받으려 나눠 결제할 수 없게 한 번에 목표 단계를 선택한다.
4. `landSubtotal + upgradeSubtotal`에서 강화 부분에만 칠색조 가호를 한 번 적용한다. 부지, 관광명소 구매, 인수 대금은 강화 할인이 아니다. 첫 구매와 동시건설도 신규 시설 부분은 할인 대상이라는 자체 제안이다.
5. 할인 후 총액과 현재 잔액을 비교한다. 정확히 같으면 성공하여 0원, 1원 부족하면 실패한다. 선택적 구매 때문에 자동 매각/파산을 일으키지 않는다.
6. 잔액·소유권·시설·가호·방문 소비·이벤트·독점 재계산을 하나로 확정한다. 실패/취소/오래된 견적이면 전부 보존한다. 성공 전에 미리 돈을 빼거나 가호를 제거하지 않는다.

## 7. 통행료·독점·가호 순서

권장 수식:

```text
base = 도시 tollByStage[현재 단계] 또는 관광명소의 고정 통행료
multiplier = 일반 도시의 해당 그룹 전체를 한 생존자가 소유하면 2, 아니면 1
gross = base * multiplier
discount = floor(gross * payerLugiaRate)    // 해당 가호가 있을 때만
payable = max(0, gross - discount)
```

도시 단계 통행료는 전체 값이며 부지/시설 통행료를 중복 합산하지 않는다. 미소유·자기 소유·출발·시험·공중날기는 0원이며 가호를 소비하지 않는다. 관광명소는 그룹 승수 대상이 아니다. 독점은 캠프 상태도 소유로 인정하고 시설 개수와 무관하다. 그룹 하나라도 소유가 끊기면 다음 견적부터 1배다. 그룹 승수와 가호 순서는 바꾸지 않는다. 공격·축제·올림픽 승수는 없다.

main에는 가호 계산이 없다. trials의 `quoteBlessing`과 일치하도록 **할인액 내림**, 나머지를 지불한다. 중간 금액을 여러 번 반올림하지 않는다. 가호율은 trials 설정값을 소비하고 UI에 50%를 박지 않는다. 기본 초안 0.5이면 101 → 할인 50 → 지불 51이다. 최소 지불액은 0이다. 할인율 1이면 양수 거래가 0원이 되고 가호는 소비된다. 할인율 0도 현재 helper는 양수 거래에 대해 소비하므로 이를 따른다. 최소 1원 규칙을 원한다면 trials와 계약 변경이 먼저다.

칠색조도 `upgradeSubtotal - floor(upgradeSubtotal * rate)`로 **합산 후 한 번** 계산한다. 강화비 0은 소비하지 않는다. 루기아/칠색조는 별개 1회권이며 누적하지 않는 trials 현재 가정이다. 견적은 소비 후보만 보여주고, 실제 통행료 의무 또는 건설이 성공 확정될 때만 소비한다. 채무 청산 중에는 최초 금액·가호율·할인액을 잠그고 재견적해 가호를 두 번 쓰지 않는다.

## 8. 관광명소 4곳과 경제 제외 칸

`kind: landmark`는 **구매 관광명소**이며 도시 최종시설 `final`과 다른 개념이다. trials v2의 ID는 `tile:kj:seafoam`, `tile:kj:power-plant`, `tile:kj:whirl`, `tile:kj:bell-tower`다. 각 250/통행료 50은 기존 seed 기반 초안이다. 별도 구매하여 소유권만 기록하고 캠프·숍·센터·최종 건설은 제공하지 않는다. 개인 해금·도시 그룹·라인 도시 개수에 넣지 않는다. 4곳 전부 소유하면 관광명소 독점 승리 후보다. 보유 개수별 통행료 추가 배율은 제안하지 않는다.

관광명소 인수는 MVP에서 불허하는 **자체 권장안**이다. 사용자 확정도, 위 공식 안내의 관광지 인수에 관한 확인 사실도 아니다. 매각·청산은 허용한다. 향후 관광명소 인수를 넣으려면 별도 정책 키로 변경한다.

`kind: start`와 trials의 `kind: special`(`lugia-trial`, `ho-oh-trial`, `fly`)에는 매입가·소유권·강화·통행료·독점이 없다. 같은 소용돌이섬/방울탑 배경이라도 `whirl`과 `lugia-trial`, `bell-tower`와 `ho-oh-trial`은 다른 ID다. 이름이나 그림으로 경제 여부를 판정하지 않는다. 비행 도착의 일반 도시/관광명소에는 정상 경제 착지를 한 번 처리하고 출발 보상·개인 바퀴수는 더하지 않는다.

## 9. 인수·매각·채무·파산

### 인수(승인 전 권장안)

타인 일반 도시에 착지하면 먼저 통행료를 정산한다. 그 뒤 살아 있고 미해결 채무가 없는 방문자만 선택적으로 인수할 수 있다. 최종시설 면역 정책이 켜져 있으면 final은 제외한다. 인수가 `2 * catalogCapital`이며 `catalogCapital = 부지 정가 + 현재까지 설치된 단계 정가 합`이다. 실제 과거 지출액/할인액/이전 인수가/독점 통행료는 원가 기준을 바꾸지 않는다. 인수금 전액을 현 소유자에게 지급하고 은행에 이중 지급하지 않는다. 양쪽 잔액 범위·소유자·시설을 재검증해 동시 이체한다.

통행료는 이미 성립한 별도 의무이므로 인수를 취소/잔액 부족으로 거부해도 되돌리지 않는다. 인수와 추가 건설을 같은 착지에서 허용하지 않는 권장안으로 가호 분할·최종시설 즉시 획득을 막는다. 시설은 그대로 이전하며 센터 재방문 기준은 새 소유자로 초기화한다. 인수 즉시 독점을 재계산한다.

### 매각·자산 평가

생존자는 자기 차례, 미해결 필수 선택이 없는 때 은행에 자산 전체를 매각할 수 있다. 채무 청산 중에는 채무자만 매각/파산 선언이 가능하다. 도시 `floor(catalogCapital * saleRate)`, 관광명소 `floor(purchasePrice * saleRate)`를 은행이 지급하며 기본 가정 `saleRate=0.5`다. 원가가 홀수면 내림, 최소 0이다. 할인 구매나 인수로 원가가 부풀지 않으며 일부 시설만 팔 수 없다. 매각 후 소유/시설/재방문 기록을 제거하고 다음 구매는 캠프부터다. 단순 평가자산은 `현금 + 각 자산 매각가`로 제공하되 시간제 승리 근거로 쓰지 않는다.

### 통행료 부족과 파산

1. 통행료 확정 시 현금이 충분하면 한 번 이체한다. 부족하면 `pendingDebt`에 채무 ID, 채무자/채권자, 최초 가호 적용 후 총액을 고정하고 **아직 통행료를 부분 이체하지 않는다**.
2. `liquidating` 상태에서는 주사위·인수·건설·턴 종료를 막고 은행 매각 또는 파산 선언만 허용한다. 매각으로 충분해지는 즉시 고정 채무를 한 번 정산한다. 가호는 이때 함께 소비한다.
3. 모든 자산을 팔아도 부족하거나 채무자가 파산을 선언하면, 남은 모든 자산을 같은 매각가로 은행 청산한다. `recovery = min(채무액, 현금 + 청산수입)`을 채권자에게 지급하고 미회수액은 소멸한다. 채무자는 현금 0/무소유/파산이 된다. 조기 파산으로 남는 초과금이 있다면 은행으로 귀속한다는 초안이며 UI에서 이를 경고한다.
4. 자산이 채권자에게 직접 이전되지는 않는다. 은행 청산으로 독점을 허위 승리시키지 않기 위한 단순 정책이다. 가호 할인 의무는 여기서도 한 번만 확정·소비한다. `toll-settled` 기록에 청구액·회수액·탕감액을 구분한다.
5. 채무·청산이 완전히 끝난 스냅샷에서 파산 이벤트와 승리 판정을 수행한다. 잔액이 정확히 0인 것 자체는 파산이 아니다. 외부 입력으로 음수 잔액/불명 소유자가 들어오면 파산 처리로 덮지 말고 invalid-state로 거부한다.

매각은 현재 방문의 건설 결정을 초기화하지 않는다. 현재 착지 도시를 매각하면 해당 방문의 부동산 결정은 완료 처리하여 같은 착지에서 재매입/재건설할 수 없게 한다. 다른 자산 매각은 현재 방문의 미사용 선택권을 유지한다. 채무 청산 중 매각은 잠긴 채무가 먼저이며 자산 매각 사이에 건설이나 승리를 끼워 넣지 않는다.

## 10. 착지·승리·중복 방지 순서

권장 경제 단계는 `awaiting-landing → settling-toll/liquidating → choosing-property → resolved`다. 코어의 `awaiting-roll/awaiting-end`를 대체한 구현이 이미 있는 것은 아니며 경제 확장 상태로 관리해야 한다.

1. 활성자·맵/프로필·revision·command ID 검증.
2. 이동 및 실제 출발 통과 보상/바퀴수 반영. 도착마다 고유 `landingId`와 방문 순번 생성.
3. 특수 칸은 trials에 위임. 그 밖에는 미소유/자기 소유/타인 소유를 분류한다.
4. 타인 소유면 통행료→필요시 청산/파산을 완료. 중간 상태에서 승리나 인수를 열지 않는다.
5. 각 소유 변화가 확정되는 경계에서 독점과 승리를 평가한다. 구매와 동시건설은 한 번의 경계다. 종료됐다면 추가 건설·인수·이동·턴 종료를 받지 않는다.
6. 아직 진행 중이면 구매/건설/인수/패스의 합법 선택을 제공하고 처리한다. 선택 완료 후 같은 착지를 재정산하지 않는다.
7. 모든 필수 선택이 끝나야 턴 종료·다음 생존자 차례를 허용한다.

승리 조건: 생존자 1명, 일반 도시그룹 3개 이상 완전 소유, 한 `side`의 일반 도시 전부 소유, 관광명소 4곳 전부 소유. trials v2는 그룹 8×3곳=24도시, 각 변 일반 도시 6곳이다. 최종시설 건설은 독점 전제가 아니다. 불완전 sample 맵은 독점 승리를 비활성화하고 완료맵 검증을 거쳐야 한다.

한 스냅샷에서 조건이 여럿이면 **최후 생존 → 관광명소 4곳 → 한 라인 → 세 그룹** 순으로 대표 사유를 선택한다(자체 제안). 부가 충족 사유는 로그에 모두 남긴다. 정상 전이에서 새 승자는 한 명이어야 한다. 외부 저장에 서로 다른 승자가 이미 있거나 생존자 0명이면 임의 차례 순으로 승자를 고르지 말고 invalid-state로 거부한다. `feat/victory`가 실제 판정기를 소유하고 경제는 각 확정 경계에 이를 호출할 확장점을 제공한다. end-turn 훅만으로 판정하면 즉시 독점 승리가 늦어지므로 부족하다.

`commandId`는 세션 내 고유하다. 같은 ID·같은 payload 재요청은 저장된 결과를 반환하되 새 이벤트·통행료·가호 소비·연출을 발행하지 않는다. 같은 ID에 다른 payload는 거부한다. `landingId`별 통행료 처리, 방문 소비, 경제 결정 완료를 기록한다. 연쇄 이동은 루트 행동 ID + 이동 순번으로 구분하여 실제 새 착지에는 한 번씩, 재생/스킵/구독 재전달에는 0번 적용한다. 비행 칸 자체는 경제 없음, 비행 목적지는 새 착지 한 번이며 한 행동의 모든 착지를 하나로 뭉개지 않는다. UI 애니메이션 완료를 경제 트리거로 사용하지 않는다.

파산 확정 후 게임이 계속되면 정산 coordinator가 활성자의 차례를 내부적으로 종료하여 다음 생존자로 넘긴다. 파산한 사용자/AI에게 종료 버튼 입력을 요구하지 않는다. 현재 코어는 `awaiting-end`의 파산자에 대한 end-turn을 허용하므로 이 경로를 한 번 호출할 수 있다. 승리가 확정됐으면 차례를 더 넘기지 않는다.

| 인수 직전 잔액450                | 통행료100 후350                  | 인수 거부, 통행료100은 유지                          |
| 센터 도시 매각                   | floor(200×0.5)                   | 100. final이면 floor(250×0.5)=125                    |
| 채무200, 현금50, 센터 자산 한 곳 | 매각100 → 가용150                | 150 회수, 50 탕감, 채무자 파산                       |

| 경계상황                                | 기대 동작                                               |
| --------------------------------------- | ------------------------------------------------------- |
| 부지 없이 센터 요청 / 목표가 현재 이하  | 전부 거부, 잔액·가호·RNG 변화 없음                      |
| 목표가 센터인데 숍 비용 생략            | 엔진이 미보유 prefix 전액 재산출, 클라이언트 금액 무시  |
| 잔액=할인 후 총액 / 1원 부족            | 전자 성공·잔액0, 후자 거래 전체 거부                    |
| 센터를 지은 착지에서 final 재요청       | 재방문 미충족, 거부                                     |
| 새 소유자가 센터 인수 직후 final 요청   | 같은 방문 거부, 다음 착지부터 재검증                    |
| 루기아 보유·무료 착지 / 100% 할인       | 무료 착지는 미소비, 양수 청구 100% 할인은 소비          |
| 견적을 여러 번 열거나 취소              | 돈·가호·방문 소비 없음                                  |
| 한 그룹의 도시 매각·인수로 소유 단절    | 다음 견적부터 그룹 배율1, 옛 quote는 stale              |
| 관광명소/시험/비행에 건설 요청          | 모두 거부. 관광명소 구매만 별도 허용                    |
| 비행으로 출발 / 본인 센터 도착          | 전자는 보상·바퀴수0, 후자는 새 방문으로 final 검증 가능 |
| 시험 중 건설·인수 / 채무 중 end-turn    | 합법행동 목록에서 제외하고 dispatch도 거부              |
| 같은 명령·착지 이벤트·연출 재전달       | 경제 처리·가호·이벤트 추가 발행0                        |
| 가격 누락, 안전정수 초과, 잘못된 프로필 | 원본 전체 보존, 명시적 오류                             |
| 매각 중 채무 충족 / 한 명만 생존        | 먼저 채무 정산, 이후 승리 평가                          |
