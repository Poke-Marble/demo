# 후속 워크트리 공통 계약

`src/game/contracts.ts`는 `schemaVersion: 1`인 **초안**입니다. 실행 규칙·승리 판정·서버 프로토콜이 아닙니다. 타입 이름을 import해 재사용하고 별도 복제 타입을 만들지 마세요. `src/game`은 `src/ui`, `src/assets`, DOM, 외부 API를 import하지 않습니다.

## 고정 ID

ID는 소문자 ASCII와 `:` 구분자를 사용합니다. 표시 이름·배열 인덱스·번역 문자열로 ID를 만들지 않습니다. 한번 발행한 ID를 다른 의미로 재사용하지 않으며, 의미가 바뀌는 경우 새 ID와 명시적인 마이그레이션이 필요합니다.

| 대상       | 규칙·예시                                                               |
| ---------- | ----------------------------------------------------------------------- |
| 맵         | `map:<slug>:<version>`, 현재 `map:kanto-johto:sample-v1`                |
| 타일       | `tile:<map namespace>:<stable slug>`, 현재 `tile:sample:pallet`         |
| 그룹       | `group:<map namespace>:<stable slug>`, 현재 `group:sample:kanto`        |
| 플레이어   | 세션 안에서 `player:1`~`player:4`, 차례 순서와 별개인 식별자            |
| 포켓몬     | `pokemon:<전국도감 4자리 이상>`, 예: `pokemon:0001`, `pokemon:0025`     |
| 스프라이트 | `pmd:<전국도감 4자리 이상>:base:<idle\|walk>`, 예: `pmd:0001:base:walk` |

`padStart(4, '0')`는 최솟값이므로 5자리 번호를 자르지 않습니다. 현재는 기본 형태만 지원합니다. 폼/색/성별 추가 시 기존 ID에 다른 이미지를 덮어씌우지 말고 새로운 형태 네임스페이스를 합의해야 합니다. 템플릿 리터럴 타입은 접두사만 제한하므로 문자열의 형식과 참조 존재 여부를 모두 보장하지 않습니다.

샘플 맵은 `completeness: 'sample'`입니다. 실제 보드의 ID·배치·완성 그룹으로 승격하지 마세요. 지도 이동 순서는 `MapDefinition.tiles`의 배열 순서이며, 시각적 변은 일반 도시의 `side`입니다. 코너의 한 변 포함 정책은 후속 설계에서 정합니다. `CityGroup.cityIds`는 일반 도시 ID만 참조합니다. 소유 정보는 타일 정의와 분리된 `GameState.holdings`에 둡니다. 특별 명소 소유 역시 이 목록에 기록할 수 있으나 시설 강화 가능 여부는 후속 규칙에서 검증합니다.

## 상태·의도·결과

- `Player`: 식별자, 이름, 선택 포켓몬, 현재 타일, 잔액, 파산 여부. `balance`는 정수 단위 금액을 전제로 하되 단위·가격은 미정입니다. 샘플의 0은 초기 자금 결정안이 아닙니다.
- `GameState`: 맵 ID, 단계, 순서가 있는 2~4인 목록, 활성 플레이어, 턴 번호, 소유·강화 상태, 승리 결과 또는 `null`. 샘플은 `setup`이며 턴 번호 0입니다.
- `Tile`: 출발 / 일반 도시 / 특별 명소의 판별 가능한 합집합. 일반 도시는 그룹과 변을 가집니다.
- `GameAction`: 주사위 요청 / 도시 구매 / 시설 강화 / 턴 종료라는 의도. 난수 결과나 비용은 UI가 전달하지 않습니다.
- `GameEvent`: 주사위 결과 / 이동 / 취득 / 강화 / 통행료 / 파산 / 턴 종료 / 승리라는 최소 결과 어휘. 이벤트 ID·순번·시간·저장 규격·재생 보장은 아직 없습니다.
- `VictoryReason`: 네 잠정 승리 조건의 식별자만 정의합니다. 우선순위·동시 충족 처리·실제 판정기는 없습니다.

모든 계약은 JSON 직렬화를 위해 함수·Date·Map·Set을 사용하지 않습니다. `readonly`는 TypeScript 수준의 제약이며 런타임 동결 또는 외부 입력 검증은 아닙니다. 후속 엔진 경계에서 인원수, 중복 ID, 참조 무결성, 활성 플레이어, 금액/단계 범위, 허용 행동을 검사해야 합니다. `players` 순서가 로컬 차례 순서이며 네트워크 사용자나 AI 종류는 이번 계약에 넣지 않았습니다.

준비 화면의 파트너 선택은 UI 메모리 상태입니다. `sampleState`는 import 가능한 최소 픽스처이며 시작 동작과 연결하지 않았습니다. 후속 시작 액션을 설계할 때 선택값을 검증하고 `GameState`를 생성하세요.
